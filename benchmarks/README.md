## Methodology

Each figure is the fastest of 7 samples, each sample a loop of enough calls to last at least 50 ms, after one warm-up sample; the garbage collector is disabled while timing. Per-call latency includes the Python call overhead, so it is the time an application actually pays. Throughput is bytes / time with 1 GB = 10^9 bytes. Payloads come from `os.urandom`; CRC speed does not depend on the data. Single-threaded unless stated otherwise, with other cores idle.

## Multi-threaded scaling

Aggregate throughput of `crc32.iscsi` on 1 MiB inputs with N Python threads. fastcrc releases the GIL for inputs of 16 KiB and more, so threads scale until memory bandwidth or the number of physical cores limits them.

| 1 | 85.6 | 1.0× |
| 2 | 163.0 | 1.9× |
| 4 | 310.1 | 3.6× |
